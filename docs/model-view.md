# Model view: plans-to-model inspection (concept visualization)

The model view is a local, bounded feature of the walkthrough viewer for this one home.
- It lets you orbit the home and switch between exterior, cutaway and translucent displays.
- You can select spaces and see what is known about each one, and on what basis.
- You can draft and save questions in the browser.

**Status:** concept visualization. It is not construction or as-built documentation, not approved architecture, and not a verified view.
It does not establish dimensional accuracy. The p6 floor plan has no dimension strings or scale bar, so every traced measurement is an estimate (E-1).

## How to open it
- Serve the project folder locally (any static server, e.g. `python3 -m http.server`).
- Open `index.html`, then press **Model**, or open `index.html?mode=model` directly.
- Deep links: `?mode=model&display=cutaway&space=bed2`. `display` takes `exterior`, `cutaway` or `translucent`; `space` takes a space id from the table below.

| Control | What it does |
|---|---|
| Drag / pinch / wheel | Orbit, zoom and pan around this home. Distance is limited to 18–300 ft, the camera stays above the ground, and the pan stays near the house. |
| Exterior | The house as modelled in the walkthrough. The other Nā Hiku homes are hidden in the model view. |
| Cutaway | A section cut at 7 ft above the floor. Roofs, ceilings and anything hung above the cut are removed, and cut walls show solid dark. Trees are hidden by default. |
| Translucent | Walls, roofs, timber and exterior trim are ghosted at 16 % opacity, with ceilings hidden. Floors, fixtures and furniture stay solid. Trees are hidden by default. |
| Rotate / Trees | Slow auto-turn, which any drag stops. Shows or hides the palms and trees. |
| Click or tap a space | Selects the floor under the pointer: the ray passes through roofs and walls. The map (bottom right) selects too. The selected space is outlined in amber, on the model and on the map. |
| Overview | The home summary: stated figures, traced totals, main assumptions and missing documents. |
| Questions (n) | Every saved question, with View (restores the display, space and camera) and Delete (with Undo for 8 s). Export JSON shows the questions as JSON with Copy JSON, plus Download file outside the private page. Copy as text copies them as plain text. Delete all needs a second tap, and any redraw of the panel disarms it. |

## What the labels mean
| Tag | Meaning | Basis |
|---|---|---|
| **SOURCE** | Stated in the Nā Hiku brochure | p6 room labels and the stated areas (2,300 / 352 / 2,652 / 494 sq ft, 4 bd / 4.5 ba); the p6 appliance labels |
| **ESTIMATE** | Scaled from the p6 plan at the fitted 23 px/ft | assumptions-register E-1 to E-4. ±3–8 % on a length, roughly ±6–17 % on an area. Every card's tag tooltip and legend say both |
| **ASSUMED** | Inferred from the p4/p5 renderings, the p7 concept board or a default | register I-1 to I-15 (heights, roof, garage, ʻohana siting, pool, lot, finishes, styling) |
| **UNKNOWN** | No document was supplied | dimensioned drawings, sections, window/door and finish schedules, electrical/lighting, site/grading/pool plans, plat |

Each space card shows a fixed set of rows:
- **Name.** SOURCE when p6 labels it; ASSUMED when the model names an unlabelled area.
- **Part of.** The stated total that the space falls under.
- **Area and overall size.** ESTIMATE, computed live from the traced polygon to wall lines, so neither net nor gross. For the garage and site, ASSUMED.
- **Ceiling.** ASSUMED, I-1/I-3. A flat value, or the vault range sampled from the modelled roof.
- **Floor finish.** ASSUMED, I-12.
- **Doors and windows.** Positions are ESTIMATE (E-2); heights are ASSUMED (I-2).
- **Fixtures and furniture.** ESTIMATE/ASSUMED (E-3, I-15).
- **Unknowns.** One row per missing document.

The area, ceiling, floor, opening-height and unknown rows each have an **Ask** button that adds a ready-made question to the draft.

The wording per space is in `plans/lot25-spaces.json`. Polygons come from `plans/lot25.json`, generated by `tools/gen_lot25.py`. Areas are computed in `src/inspect.js`, so they always match the model.

## Questions stay on this device
- Drafts save as you type, each to its own space. Saved questions go to the browser's `localStorage`, under the keys `nahiku.lot25.drafts.v1` and `nahiku.lot25.questions.v1`.
- Storage is read again before every change and followed across tabs, so two open tabs add to each other's questions instead of overwriting them.
- Each saved question records the space, the display and the camera, so **View** can return to it.
- **Nothing is sent anywhere.** The model view makes no network requests.
- **Export JSON** shows the questions as JSON (format `nahiku-questions/1`, carrying the concept-visualization label). **Copy JSON** puts it on the clipboard. **Download file** saves `nahiku-lot25-questions.json` where the browser allows page downloads; the private claude.ai page does not. If the clipboard is blocked, the text is left selected for copying by hand.
- If the browser blocks storage (some private modes), the panel says so, and questions last until the page is reloaded.
- The walkthrough's existing live weather (`src/weather.js`) asks Open-Meteo for the site's current weather unless `?wx=` or `?weather=` is given. That request carries only the fixed site coordinates, never questions.

Fixed during QA:

Not covered by the automated run:
- Hover tooltips (desktop mouse only).
- Clipboard copy (needs a permission grant).
- Night lighting in the model view.
- Real-GPU frame rates. SwiftShader is far slower than a phone or laptop GPU.
- The ultra/high quality path. AO is switched off in cutaway and translucent by design; the exterior display keeps it.

## Private page build
`python3 scripts/build_artifact.py <dir>` makes the copy published as a private claude.ai page. That page opens only for the account that owns it, unless the owner shares it.

The host wraps the page in its own document, admits scripts only from a few CDNs and passes no query string. So the copy:
- drops the skeleton tags;
- loads three.js 0.160.0 and astronomy-engine 2.1.19 from jsDelivr. Those are the same files `vendor/` holds: three.js byte-identical, astronomy-engine as the unminified source;
- opens in the model view;
- hides the Ultra button and the 360° tour link.

It publishes only `src/`, `plans/`, `data/` and `geodata/`, about 10 MB.

## Not claimed
- Buyer readiness, approved architecture, construction readiness or as-built accuracy.
- Any dimension beyond the stated p6 areas. Traced sizes are estimates against a fitted scale.
